## О проекте

autodq — приложение для контроля качества табличных данных. Статистическое ядро строит профиль эталонного CSV, предлагает правила, выполняет подтверждённые правила на новом срезе и формирует отчёт. Браузерный интерфейс показывает демоданные и открывает JSON-отчёты локального анализа.

Пользователь проверяет предложенные правила и выбирает, какие из них применять к новым срезам.

## Локальный запуск

Выполните команды в корне проекта с Node.js 22.12+.

~~~sh
npm ci
npm run dev
~~~

Откройте [http://localhost:5173](http://localhost:5173). Команда `npm run build` создаёт статическую сборку в `dist/`, а `npm run preview` запускает её предпросмотр.

Для анализа CSV установите ядро в виртуальное окружение с Python 3.11+ и запустите пример.

~~~sh
python -m pip install -e .
python examples/generate_snapshots.py
autodq profile autodq-runs/reference.csv -o autodq-runs/profile.json
autodq fit autodq-runs/reference.csv -o autodq-runs/suggested.json
autodq review autodq-runs/suggested.json --approve-all -o autodq-runs/approved.json
autodq check autodq-runs/stable.csv --rules autodq-runs/approved.json -o autodq-runs/stable.json
autodq check autodq-runs/shifted.csv --rules autodq-runs/approved.json -o autodq-runs/shifted.json --html autodq-runs/shifted.html
~~~

В примере намеренно внесены пропуски, дубликаты, новые категории и сдвиг числового распределения. Проверка `shifted.csv` возвращает код 2 и сохраняет оба отчёта. Чтобы открыть её результат в приложении, выберите **Отчёты → Отчёт локального анализа** и загрузите `shifted.json`. Браузер читает файл локально.

Для своих данных передайте два независимых снимка с сопоставимым составом строк. Просмотрите `suggested.json` и одобрите подходящие правила параметром `--approve RULE_ID`. Параметр можно указать несколько раз. Подробности об объектах Python, статистике и результатах описаны в [документации ядра](docs/engine.md).

## Как это работает

```
 источник данных ──▶ профиль ──▶ правила ──▶ проверки ──▶ отчёт
                      │            │            │           │
            типы, пропуски,   предложены    выполнены    индекс,
            уникальность,     с оценкой     на новом срезе нарушения,
            распределения,    уверенности,  результаты   классы
            диапазоны,        подтверждены  сохранены    проблем
            частоты           пользователем
```

1. **Профилирование.** Для каждой колонки считаются тип, доля пропусков, уникальность, распределение, квантили, диапазон, частоты значений.
2. **Генерация правил.** Ядро предлагает проверки полноты, типа, диапазона, категорий, уникальности ключей и дрейфа распределений.
3. **Подтверждение.** Пользователь принимает или отклоняет предложенные правила по их ID.
4. **Выполнение.** CLI запускает одобренные правила на новом срезе и сохраняет результат по каждому правилу.
5. **Отчёт.** Индекс качества, отклонения от профиля, классификация проблем: полнота, уникальность, диапазон, формат, согласованность, своевременность, распределение.

## Модули

| Модуль | Что делает | Статус |
|---|---|---|
| `profiling` | Логические типы, пропуски, частоты, квантили, медиана и MAD | локальный анализ |
| `rules` | Обнаружение кандидатов, калибровка и ревью | локальный анализ |
| `checks` | Сравнение нового среза с эталоном по одобренным правилам | локальный анализ |
| `reporting` | Машиночитаемый JSON и самостоятельный HTML | локальный анализ |
| `src` | Рабочее пространство Vue и просмотр JSON-отчётов | деморежим |
| `backend` | Контракты FastAPI и черновик адаптеров хранения | заготовка |

## Статус

Локальный анализ работает с CSV. Подключения к источникам, серверный регламент, уведомления, аутентификация и лицензирование представлены в интерфейсе как демонстрационные состояния. План подключения хранилища находится в [backend/storage.py](backend/storage.py).
