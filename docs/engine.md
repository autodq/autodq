# Статистическое ядро AutoDQ

## Контракты

| Шаг | Вход | Выход |
| --- | --- | --- |
| Чтение | UTF-8 CSV с заголовком | `Table` с именованными колонками одинаковой длины |
| Профилирование | `Table` | `DatasetProfile` с типами, счётчиками, частотами и числовой статистикой |
| Обучение | Эталонный `Table` и `FitConfig` | `RuleBook` с правилами в статусе `suggested` |
| Ревью | `RuleBook` и отображение ID в `Status` | Новая версия объекта `RuleBook` |
| Проверка | Новый `Table`, `RuleBook` и `CheckConfig` | `Report` с результатом, покрытием и оценкой качества |
| Просмотр | `Report` | JSON для приложения или самостоятельный HTML |

Контракты определены в `engine/autodq/models.py`. Pydantic проверяет поля при чтении JSON, а версия формата записана в `RuleBook` и `Report`. Спецификация каждого правила выбирается по полю `spec.kind`. В CSV пробельные и пустые поля считаются пропусками. Текстовое значение `NULL` сохраняется как значение. При сравнении категорий и ключей учитывается исходный текст.

~~~python
from pathlib import Path

from autodq import check, fit, review
from autodq.models import CheckConfig, Status
from autodq.table import read_csv

book = fit(read_csv(Path("reference.csv")))
# selected_ids заполняет оператор после просмотра book.rules.
selected_ids = [rule.id for rule in book.rules if rule.spec.kind == "missing"]
approved = review(book, {rule_id: Status.APPROVED for rule_id in selected_ids})
report = check(read_csv(Path("current.csv")), approved, CheckConfig())
print(report.model_dump_json(indent=2))
~~~

## Обучение и проверка

Эталон делится воспроизводимо на выборки обнаружения и калибровки. На первой определяются типы, границы диапазонов, словари и границы гистограмм. На второй оценивается покрытие правил и строятся эталонные гистограммы. Для обучения стандартная конфигурация требует от 60 строк. Минимум по каждому отдельному правилу учитывает число пригодных наблюдений.

| Правило | Как строится | Что измеряется на новом срезе |
| --- | --- | --- |
| `missing` | Доля пропусков на калибровке | Рост доли пропусков |
| `type` | Булевый, целый, числовой, ISO-дата или ISO-дата-время с достаточной долей совпадений | Рост доли значений с конфликтом типа |
| `range` | Эмпирические квантили по краям эталонного распределения | Рост доли числовых значений за границами |
| `in_set` | Словарь колонки с малым числом различных значений | Рост доли новых значений |
| `unique` | Колонка `id`, `uuid`, `*_id` или `*_uuid`, уникальная на обеих частях эталона | Доля повторных непустых значений после первого вхождения |
| `drift` | Фиксированные границы по квантилям или эталонный словарь с корзиной для новых значений | Расстояние Дженсена — Шеннона и условный тест однородности гистограмм |

Пропуски оцениваются отдельно. Правила диапазона и числового дрейфа используют только конечные распознанные числа. Именованные идентификаторы исключены из обучения диапазонов и гистограмм. Полностью пустая колонка остаётся в профиле и в проверке схемы.

Для бинарных правил сохраняется односторонняя нижняя 95%-ная граница покрытия Уилсона. Деградация на новом срезе проверяется односторонним точным тестом Фишера. Для дрейфа расстояние Дженсена — Шеннона при основании 2 измеряет величину сдвига от 0 до 1. Статистическая значимость проверяется условным тестом Пирсона с фиксированными суммами таблицы и моделированием по многомерному гипергеометрическому распределению. Число симуляций адаптируется к размеру семейства гипотез с пределом 200 000 на правило. Для больших семейств или очень малого уровня значимости этот предел ограничивает разрешение теста.

Поправка Холма применяется ко всем вычисленным p-значениям текущего запуска. При стандартных параметрах для `fail` статистическое подтверждение должно сопровождаться ростом доли нарушений не менее чем на 2 процентных пункта либо расстоянием Дженсена — Шеннона от 0.10. При заметном эффекте и слабом статистическом подтверждении результат получает `warn`. Уникальность проверяется по жёсткому пределу доли дублей. При недостатке наблюдений конкретное правило получает `skip`. Отсутствующая колонка приводит к `fail` на уровне набора.

Оценка качества — доля результатов `pass` среди оценённых правил, умноженная на 100. Покрытие — доля оценённых среди одобренных. Обе метрики показываются вместе. Код CLI `0` означает `pass` или `warn`, `2` означает `fail`, `3` означает `skip`, `1` означает ошибку входных данных или записи.

CSV читается в память. Для зависимых рядов, повторных наблюдений одной сущности и сезонных данных нужен способ разбиения и сравнения, соответствующий структуре выборки. Артефакты профиля могут содержать исходные частые значения и словари категорий. Проверки свежести требуют согласованного времени запуска, а проверки внешних ключей требуют справочника. Эти проверки, блоковое сравнение и распределённое чтение остаются задачами следующего этапа.

### Источники методов

- Нижняя граница покрытия. [NIST Engineering Statistics Handbook](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)
- Точный тест Фишера и выбор из фиксированных сумм. [SciPy](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.fisher_exact.html)
- Дивергенция Дженсена — Шеннона. [Jianhua Lin, 1991](https://doi.org/10.1109/18.61115)
- Поправка для семейства гипотез. [Sture Holm, 1979](https://www.ime.usp.br/~abe/lista/pdf4R8xPVzCnX.pdf)

## Шаблон сервера

`backend/api.py` объявляет входные и выходные модели FastAPI. Для просмотра Swagger и OpenAPI запустите каркас.

~~~sh
python -m pip install -e ".[api]"
python -m uvicorn backend.api:app
~~~

`/docs` открывает Swagger, `/openapi.json` отдаёт контракт, `/api/v1/health` показывает состояние каркаса. Обработчики анализа возвращают `501`. В них отмечены точки вызова ядра. `backend/storage.py` описывает будущие адаптеры и хранение версий, запусков и расписаний комментариями.
